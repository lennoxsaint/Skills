# Release And External-Action Closeout

Apply the user's standing rules on what may be released, and any project-specific gate. This reference grants no new authority. Finish preparation before an approval gate; do not infer release authorization from permission to build or review.

For an authorized action, record the target, action and tool, timestamp, before and after proof, and recovery path. A release that was attempted and stopped is recorded the same way, with what stopped it. Read back the provider or runtime outcome. Keep local, staged, scheduled, deployed, published and delivered states separate.

For automations, inspect actual run history and next-run evidence; an ACTIVE flag alone proves configuration only. For a host's native state, such as a goal mode or a scheduler, verify the requested control itself. Report a missing receipt or unavailable readback rather than promoting an attempted action to success.

Rollback must be possible or its absence stated. Never perform unrequested destructive cleanup. Record the actual outcome, including partial or blocked releases.
